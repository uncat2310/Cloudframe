Cloudframe 是一个部署在 Cloudflare 上的私人图床面板：图片存放在你自己的 R2 存储桶里，面板负责上传和管理，只用一个密码，就能在任何设备上打开使用。这篇教程从部署讲起，覆盖上传、画廊、设置与安全。

开始部署 → 先看功能
个人使用免费 Workers 方式不需要 R2 API 令牌 图片外链不经过面板

01三步看懂它怎么工作

🪣

准备一个 R2 存储桶

在 Cloudflare 创建存储桶并开启公开访问，图片就存在这里，归你所有。

🖼️

部署面板

面板跑在 Workers 上，通过绑定直接读写存储桶。浏览器只和面板说话，拿不到任何 R2 密钥。

🔑

设个密码，开用

打开你的域名，输入密码即可。换设备、换浏览器，同一套设置跟着你走。

核心原则：图片的展示和外链直接走 R2 的公开地址，不经过面板。哪天不用这个面板了，已经发出去的链接照样能打开——图片永远不被面板「绑架」。

02部署到 Cloudflare Workers（免费）

三种部署方式里最推荐这一种：个人使用免费，不需要创建 R2 API 令牌，全程在 Cloudflare 后台点选完成，不用装任何工具。完整版见仓库的 部署指南，这里是主干流程。

  1. 创建 R2 存储桶，开启公开访问

    Cloudflare 控制台 → R2 → 创建存储桶。然后进存储桶设置开启公开访问，二选一：绑定自定义域名（推荐，能走 Cloudflare 缓存），或启用 r2.dev 子域名（有速率限制，只适合轻量使用）。记下这个公开地址，后面要用。不需要给存储桶配 CORS。

  2. Fork 仓库，改一处配置

    在 GitHub 上 Fork 本仓库，编辑 apps/web/wrangler.jsonc：把 bucket_name 改成你的存储桶名，R2_PUBLIC_URL 填上一步的公开地址（不要带结尾的 /）。没有自己的域名时，把 workers_dev 改成 true，否则部署完没有访问地址。binding 保持 BUCKET 不动；kv_namespaces 里的 id 是原作者账号的，先删掉这一段或之后按「设置同步」换成你自己的。改完提交到 main。

  3. 在 Cloudflare 导入 Git 仓库

    控制台 → Workers 和 Pages → 创建 → Connect GitHub，只授权你 Fork 的这一个仓库。填写：项目名称 cloudframe（与配置里的 name 一致）、构建命令和部署命令如下，根目录保持默认。点部署，等大约 2 分钟构建完成。建议随后在 Worker 设置里关闭「预览分支构建」，免得以后其他分支的推送出现失败检查。

    # 构建命令
pnpm --filter cloudframe-web build:worker
# 部署命令
pnpm --filter cloudframe-web deploy:worker
  4. 添加登录密码和会话密钥

    Worker → 设置 → 运行时变量和密钥（确认在「生产」环境），添加两个变量，都务必勾选「密钥」，让值加密保存：

    CLOUDFRAME_PASSWORD        # 你的登录密码，建议 16 位以上随机字符
CLOUDFRAME_SESSION_SECRET  # 签名登录 cookie 的随机串，终端运行 openssl rand -base64 32 生成

    保存后检查这两行的类型显示为「密钥」、值显示「值已加密」；如果能看到明文，说明没勾对，删掉重加。

  5. 绑定自己的域名

    Worker → 域 → 添加域名，选你托管在 Cloudflare 的域名，填子域名（例如 pic）。DNS 和证书会自动创建，一两分钟后就能打开。没有域名就跳过这一步，用 https://cloudframe.<你的子域>.workers.dev 访问（需第 2 步已把 workers_dev 设为 true）。

  6. 打开域名，输入密码

    部署完成。之后每次推送到 main 都会自动重新部署；面板出问题时，可以在 Worker 的 Observability 里看日志。

03部署后推荐设置

下面四项都不是必需的，但强烈建议顺手做完，每项在部署指南里都有逐点击的步骤。

🚦

登录限速规则

应用自带的限流是近似计数。在域名上再加一条 Cloudflare 免费的速率限制规则（针对登录接口、单 IP 10 秒最多 4 次），能精确挡住暴力猜密码。需要自定义域名，且 workers_dev 保持 false 才不会被绕过。

部署指南 2.5
⚡

画廊缩略图

开启 Cloudflare 图片变换后，画廊只加载长边 800 像素的缩略图（通常几十 KB），点开和下载仍是原图。免费版每月 5,000 张不同缩略图，个人使用绰绰有余；超额时自动回退显示原图，不产生费用。

部署指南 2.6
🔄

设置同步

创建一个 Workers KV 命名空间，把 ID 填回配置，压缩、路径模板和画廊设置就保存在服务器上，所有设备共用一套。改完约 1 秒自动保存；语言和主题仍跟随各自的浏览器。

部署指南 2.7
🗑️

回收站自动清理

删除的图片先去存储桶的 .trash/ 目录，30 天内可恢复。给存储桶加一条对象生命周期规则（前缀 .trash/，30 天后删除），再加一条规则禁止公开访问回收站，就齐了。注意前缀一定要填，留空会作用于整个存储桶。

04另外两种部署：Docker / Node

想把面板跑在自己的服务器或电脑上也可以。区别是这两种方式要先在 R2 概览页创建 API 令牌（权限选「对象读和写」，限定到你的存储桶），并记下账户 ID、访问密钥 ID 和机密访问密钥。

Docker（VPS 或常开的电脑）

git clone <你的仓库地址> cloudframe
cd cloudframe/selfhost
cp .env.example .env   # 填入 R2 信息和登录密码
docker compose up -d --build

浏览器打开 http://服务器IP:3000 输入密码即可。设置保存在数据卷 cloudframe-data 里，重建容器不丢失。更新版本就是 git pull 后再 docker compose up -d --build。

直接运行 Node

pnpm install
pnpm --filter cloudframe-web build
cp selfhost/.env.example selfhost/.env   # 然后编辑
node --env-file=selfhost/.env apps/web/.output/server/index.mjs

默认监听 3000 端口，可用 PORT 修改。需要 Node.js 22 和 pnpm（corepack enable）。

环境变量速查（Docker / Node）

变量必填说明
CLOUDFRAME_PASSWORD是面板登录密码
R2_ACCOUNT_ID是*Cloudflare 账户 ID，用来拼 S3 Endpoint；填了 R2_ENDPOINT 可免
R2_ACCESS_KEY_ID / R2_SECRET_ACCESS_KEY是API 令牌的密钥对
R2_BUCKET是存储桶名称
R2_PUBLIC_URL是公开访问地址（自定义域名或 r2.dev）
CLOUDFRAME_SESSION_SECRET否会话签名密钥，默认用 R2_SECRET_ACCESS_KEY
R2_INCLUDE_PATH否只让面板看某个前缀下的文件，例如 i/
CLOUDFRAME_THUMBNAILS否设为 cloudflare 开启画廊缩略图
CLOUDFRAME_CLIENT_IP_HEADER否放在反向代理后面时，按真实 IP 限流用的请求头；没有代理时不要设

配置不完整时，面板会直接列出缺了哪个变量，服务器日志里也会打印，不用猜。

05上传与画廊

上传

  • 三种姿势：把文件拖进窗口、在页面上直接粘贴、或者点选文件。
  • 上传前处理：可以先压缩，并转换格式（WebP / AVIF / JPEG / PNG），大图发外链也不心疼流量。
  • 路径模板：用模板决定图片在存储桶里的存放路径，例如 i/{{year}}/{{month}}/{{day}}/{{ulid-dayslice}}.{{ext}} 会按日期分文件夹、用 ULID 命名。占位符全集见设置说明。
  • 能传什么：只允许图片和视频（Live Photo 的 .mov 也算），其他类型会被拒绝。

画廊

  • 网格浏览，按名称搜索，按日期筛选和排序，图多也不乱。
  • 支持 HEIC 和 Apple Live Photo——经由面板转发，浏览器里能直接看。
  • 开了缩略图后（见「部署后推荐设置」），画廊加载的是小图，点开才是原图。

06分享与管理

  • 分享：点一下复制图片链接，或者直接复制 Markdown 格式，贴进文章就能用。这些链接走 R2 公开地址，不经过面板。
  • 管理：重命名、删除、下载都在画廊里完成。
  • 回收站：删除不是立刻消失——图片先移到回收站，30 天内可以在「设置 → 回收站」里恢复或永久删除（回收站的自动清理规则见部署指南 2.8）。

小提示：上传、删除、重命名、列出文件，以及 HEIC / Live Photo 的读取会经过面板；普通图片的展示和外链直接走 R2，不耗面板的请求额度。

07设置速查

  • 上传设置：压缩开关与目标格式、路径模板与预设——决定每张新图怎么存。
  • 画廊设置：排序、显示选项等浏览偏好。
  • 设置存哪：开启设置同步（Workers KV 或 Docker 的 /data 目录）后，设置存在服务器上，所有设备一致；没开启时，存在各自的浏览器里。语言和主题始终跟随浏览器，不同步。
  • 存储桶范围：R2_INCLUDE_PATH 可以把面板限定在一个前缀里；CLOUDFRAME_KEY_TEMPLATE 可以预设新浏览器的默认路径模板。

每一项设置的完整说明在仓库的设置说明（中文） / Settings reference (English) 里，面板设置页的帮助链接也指向它们。

08安全

面板只有一个密码，而密码背后是你整个存储桶，所以这部分值得认真看：

  • 密码要长：16 位以上的随机密码。它就是存储桶的钥匙。
  • 登录有限流：每个 IP 每分钟最多 10 次、所有来源合计每分钟最多 60 次；Workers 上用 Cloudflare 提供、无法伪造的客户端 IP。再配合域名上的速率限制规则（部署指南 2.5），猜密码基本没戏。
  • 会话：登录状态是签名的 HttpOnly、SameSite=Strict cookie，有效期 30 天。「退出登录」只清当前浏览器；想让所有设备立即失效，改 CLOUDFRAME_SESSION_SECRET 或密码即可。
  • 为什么建议设 SESSION_SECRET：不设也能用，但 cookie 只用由密码派生的密钥签名，一旦泄露就可能被离线爆破出密码；设了之后没有这个隐患，日常使用无区别。
  • 文件与响应：只允许上传图片和视频；通过面板读取的文件在沙箱中返回，不会被当成网页执行；所有响应都带安全响应头（禁止被嵌入、禁止 MIME 嗅探、HSTS 等）。
  • Docker / Node 注意：暴露到公网时务必加 HTTPS，否则密码明文传输。用 Caddy 反代最省事，还能自动签证书：
panel.example.com {
    reverse_proxy 127.0.0.1:3000
}

09免费额度

个人图床基本用不完这些额度，心里有个数就行：

服务免费额度
Workers每天 10 万次请求；每次请求 10 ms CPU 时间（等 R2 的时间不计）
R2每月 10 GB 存储、100 万次写类操作、1,000 万次读类操作；流量免费
Workers KV（设置同步）每天 10 万次读、1,000 次写
图片变换（缩略图）每月 5,000 张不同的缩略图，超额自动回退原图、不收费

上传特别大的图片偶尔失败，多半是超了单次请求的 CPU 时间：先在上传设置里开启压缩，或者升级 Workers 付费版。

10常见问题

没有自己的域名，能用吗？

能。把 wrangler.jsonc 里的 workers_dev 改成 true，用 workers.dev 地址访问面板；图片公开地址用存储桶的 r2.dev 子域名。只是画廊缩略图和域名级限速规则需要自定义域名才能开。

部署完了打不开、没有访问地址？

多半是 workers_dev 是 false 又还没绑域名。绑上域名，或者把 workers_dev 改成 true 重新部署即可。再检查两个密钥变量是不是加在了「生产」环境。

画廊打开很慢，图片一张张慢慢出。

按部署指南 2.6 开启图片变换并把 CLOUDFRAME_THUMBNAILS 设为 cloudflare，画廊就会只加载 800 像素的缩略图。注意存储桶公开地址要绑在你自己的域名上，r2.dev 地址开不了。

换了个浏览器，设置不一样了。

说明还没开设置同步。按部署指南 2.7 创建 KV 并把 ID 填回配置，之后所有设备的设置就统一了。第一次开启时，以最先登录的那个浏览器里的设置为准。

删掉的图片去哪了？

进了存储桶 .trash/ 目录下的回收站，保留原路径。30 天内去「设置 → 回收站」可以恢复或永久删除；想让它 30 天后自动清掉，别忘了加对象生命周期规则（部署指南 2.8）。

忘了密码，或者想让所有设备重新登录。

密码存在 Worker 的密钥（或 Docker / Node 的 .env）里，改掉它并重新部署即可。改 CLOUDFRAME_SESSION_SECRET 也会让所有已发出的登录 cookie 立即失效。

面板和原项目 S3 Image Port 是什么关系？

Cloudframe 基于 S3 Image Port 改造，只保留自部署模式、专门适配 Cloudflare R2：去掉了浏览器端填 S3 参数、多配置和配置同步，登录与上传做了安全加固。上传、画廊、压缩、HEIC / Live Photo 等核心能力都来自原项目。
